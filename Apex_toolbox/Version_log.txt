v3.7 beta 3 Changes:
	"Both versions":
	Auto_tex: full RSX (RSX -> CAST -> Blender) compatibility, without losing Legion+ support.
	The texture lookup was rebuilt around the semantic information the CAST import leaves in the material,
	instead of around the old "<material name>_albedoTexture.png" filename assumption.
	- Reads the roles straight out of the imported node graph (Principled and Eevee Specular), so RSX
	  "Real", "Text", "Semantic" and even "GUID" texture naming all work. A 0x1234ABCD.png the CAST
	  importer bound to the normal socket is used as the normal map, no filename guessing involved.
	- Nodes are found by type, not by the names "Image Texture" or "0". Renamed and .001 nodes work.
	- Added the RSX/Respawn short texture codes (_col _nml _spc _gls _ao _cav _ilm _thk _opa _asd)
	  alongside every classic _albedoTexture style name.
	- Texture-family matching: a material only picks up textures from its own family, so a body material
	  can no longer grab the head material's textures out of a shared folder.
	- Mips and array variants (_001, _level1, _1_col) are recognised as variants, never as roles, and the
	  full resolution image is always preferred.
	- Gloss vs roughness is tracked properly. A roughness map is inverted into glossiness in the node
	  graph (gloss = 1 - roughness); a real gloss map is never inverted.
	- Auto_tex is now non-destructive: it captures, resolves and validates BEFORE it rebuilds. If nothing
	  can be resolved (for example RSX exported with "Export Material Textures" off) the imported material
	  is left untouched instead of being cleared.
	- Ambiguous matches are reported instead of guessed. A wrong texture is worse than a missing one.
	- Re-running Auto_tex, or switching between the three shaders, now keeps every texture.
	- New optional "Textures Folder" / "Search Sub-folders" fields in the Auto_tex tab. Only needed when
	  the imported material references no images at all.
	- Much clearer console output: one summary block per material saying where every texture came from.
	Fixes:
	- Apex Shader+ v3.4 never actually received Scatter Thickness, Opacity or Alpha: Auto_tex asked for
	  sockets named "SSS Map" and "Alpha", which that group does not have, and the failed links were
	  swallowed by a bare except. Now connected. Same fix for S/G-Blender ("Alpha input").
	- Extensions are read with os.path.splitext instead of split(".")[1], so filenames containing more
	  than one period no longer break.
	- Formats other than PNG (DDS, TGA, TIFF, JPG, EXR, ...) are accepted.
	See RSX_COMPATIBILITY.md inside the addon folder for the recommended RSX settings.
	Restart Blender after update.

v3.7 beta 4 Changes:
	"Both versions":
	This is a maintenance and cleanup release. Beta 3's RSX/CAST texture resolver is unchanged in
	behaviour except where noted; everything around it was tidied up.

	Auto Texture:
	- No longer needs a texture folder. It works out where the export lives from the collection the
	  CAST importer created, Blender's own file browser history, and export folders it remembers from
	  previous successful runs. Import CAST -> select model -> Texture Model.
	- The Texture Search Folder is now an optional override under "Search Options", not a requirement.
	- Successful runs remember the export folder, so every later model from the same export resolves
	  with no interaction, including in a new Blender session. Preferences lists and clears them.
	- The console says where it searched and how many textures it resolved.
	- If two copies of a model exist on disk, the one you just imported from wins.

	UI:
	- The sidebar is rebuilt from real Blender panels instead of nine hand-rolled fold-outs in one
	  360-line draw(): Model / Materials (Auto Texture, Recolour, Toon) / Shaders & Environment /
	  Rigging & Animation / Effects (Auto Shadow, Apex Effects, Scene Utilities) / About & Help.
	- Instructions, credits, links and the update tracker moved out of the main workflow into
	  "About & Help".
	- Clearer names: Auto_tex -> Auto Texture, Auto_shadow -> Auto Shadow, Re-color -> Recolour,
	  "Append Shaders & HDRI" -> "Shaders & Environment", "Add Shader" -> "Add Selected Shader".
	- Buttons that cannot work yet are greyed out instead of failing.
	- The ambiguous "Folder:" fields are now "Toolbox Assets Folder" and "Legion+ Parent Folder", and
	  the add-on Preferences page is no longer blank.
	- The twelve "-----" separator rows are gone.

	Repairs (all verified against Blender 4.0 and 4.2):
	- Toon It was broken on Blender 4.2: it set render.engine to "BLENDER_EEVEE", which 4.2 renamed.
	  It also still used the pre-beta-3 texture lookup, so it failed on every RSX export. Both fixed;
	  Toon now shares the Auto Texture resolver.
	- Add IK Bones was broken on every supported Blender: it passed "orient_axis_ortho" to
	  transform.translate, which no longer accepts it. Fixed, and it no longer crashes with nothing
	  selected.
	- Auto Shadow "Adjust and Parent" raised UnboundLocalError on any rig without a nose bone. It now
	  says what it looked for.
	- "Check for Updates" aborted partway through: the cast plugin changed its release title format
	  and the unguarded parser raised IndexError. Fixed, and the io_model_semodel link no longer opens
	  the wrong project.
	- Every bpy.context.preferences.addons["Apex_toolbox"] lookup is gone. Those raised KeyError if the
	  add-on folder was not named exactly "Apex_toolbox", which is what happens when you install a
	  GitHub "Download ZIP".
	- Blender no longer stalls at startup: the add-on used to make a GitHub request with no timeout
	  while it was being imported. The check now runs only when you press the button.
	- The add-on no longer switches your "Relative Paths" preference off just by loading.
	- Instructions / Version Log no longer take over whichever editor you clicked in.
	- Set Correct Model Size, Toon It, Recolour and Add IK Bones report what they need instead of
	  printing to the console and doing nothing.
	- Actions that need the Assets pack say so instead of failing on a missing Assets.blend.
	- Built-in HDRI files are opened by their real lowercase names (matters off Windows).

	Update tracker:
	- This build is a fork, so it no longer reports the original add-on's release numbers as if they
	  were its own. Set "Releases Repository" in Preferences to owner/name to track this build; leave
	  it empty to disable the notice. The original project is still linked under About & Help.

	Removed:
	- The "LEGION MODELS TRANSLATE" panel: the whole class sat inside a string literal and had never
	  been registered.
	- The developer "test mode" branches with hardcoded personal drive paths.
	- The "Current Mode" row from the top of the panel (it is a compact status line now).
	No button a user could click was removed.

	Recolour now shares the Auto Texture resolver, so RSX-named recolour folders work too.
	Restart Blender after update.

v3.7 beta 4.1 Changes (hotfix):
	"Both versions":
	Fixes a crash in v3.7 beta 4 when Auto Texture / Texture Model was clicked after installing
	beta 4 over an already-running older version:
		TypeError: run() got an unexpected keyword argument 'remembered_roots'

	Cause: Blender re-executes an add-on's top level __init__.py when the add-on is re-enabled, but
	leaves any submodule that is already in sys.modules untouched. Installing beta 4 over a running
	beta 3 therefore left beta 4's caller talking to beta 3's apex_tex.autotex. Nothing was wrong with
	the shipped files; the archive and the installed copy were both correct beta 4.

	- The add-on now reloads its apex_tex submodules, dependencies first, whenever it is re-enabled,
	  so a hot upgrade can no longer mix revisions.
	- apex_tex carries an API_VERSION that __init__.py checks. If a stale module ever survives anyway,
	  Auto Texture, Toon and Recolour stop with "Apex Toolbox was updated while Blender was running.
	  Restart Blender to finish the update." and the panel shows the same warning, instead of failing
	  with a Python traceback.
	- remembered_roots / extra_roots accept None safely; no mutable default arguments anywhere in
	  apex_tex.

	New tests, so this class of fault cannot ship again:
	- A static contract test parses every apex_tex call in __init__.py and checks each keyword against
	  the real function signature, plus the API_VERSION agreement and the reload order.
	- A fresh-install test installs only the packaged ZIP into an empty add-ons location and runs
	  Texture Model from that copy (cold zero-config, remembered root, and manual folder).
	- An upgrade test installs beta 3, then beta 4.1 in the same session, and runs Texture Model.

	No behaviour changes: automatic texture discovery, remembered roots, collection-name RSX
	discovery, Blender bookmarks discovery, the manual folder fallback, Search Sub-folders, the
	beta 3 resolver, legacy Legion support and the root priority rules are all unchanged.

	Note: the unsafe world nodes['Mapping'] lookup that spammed tracebacks from the panel draw() was
	already fixed in beta 4; it only occurs on beta 3 and earlier.

	Downgrading to beta 3 or earlier in a running session still needs a Blender restart, because those
	versions have no reload handling.
